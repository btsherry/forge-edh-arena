# Building forge-arena

`forge-arena` is a module inside a full fork of [Card-Forge/forge](https://github.com/Card-Forge/forge).
It adds a headless/observable 4-player Commander harness with per-seat AI. This
file is the build recipe — the root `README.md` is Forge's generic one and does
not cover the arena.

## Prerequisites

- **JDK 17+** (the project targets 17; the recorded green gates since late August ran on JDK 25 — both work). Scripts honor `$JAVA_HOME`
  if set, otherwise `java` on `PATH`.
- **Maven 3.8+** and **git**.
- **Network access for the first build** (Maven downloads Forge's dependencies
  from Maven Central into `~/.m2`). Only after that cache is warm can you use
  the offline `-o` flag.
- Disk/patience: this is a fork of all of Forge — the clone is large
  (`forge-gui/res` alone is ~450 MB of card data) and a full build compiles
  every module and runs the arena test gate (budget ~10–15 min the first time,
  ~8–10 min after).

## Build

From the **repository root**:

```sh
# First build (online — populates ~/.m2):
mvn -pl forge-arena -am package

# STANDARD gate (harness boil, 2026-08-28) — parents build, their tests skip,
# the arena suite still runs (arena's surefire deliberately ignores
# -DskipTests via its own arena.skip.tests property):
mvn -o -pl forge-arena -am package -DskipTests

# FULL gate — required whenever the change-set touches a parent module
# (forge-ai / forge-game / forge-core / forge-gui*) and on every
# UPSTREAM-SYNC import; otherwise upstream tests re-verify nothing:
mvn -o -pl forge-arena -am package
```

Yes, `-DskipTests` running the arena tests looks paradoxical — it is
deliberate (see the surefire comment in `forge-arena/pom.xml`): upstream
modules honor the flag, the arena suite ignores it. `-Darena.skip.tests=true`
is the explicit arena opt-out (used by `batch.sh`).

Only `-DskipTests` is neutralised. **`-Dmaven.test.skip=true` DOES skip the
arena suite** (and its test compilation) exactly as it does for every other
module — the arena pom does not override that property. A build run with it
is not a gate; never quote one as green.

Two more surefire knobs (both added 2026-09-04, BL-25):

- **`arena.excluded.groups`** (default `extended`). Tests tagged with the
  TestNG group `extended` are skipped by the STANDARD gate so its time does
  not grow; the FULL / release gate passes `-Darena.excluded.groups=none` to
  run them. As of 2026-09-04 the group is wired in the pom but no test in
  the tree carries it yet — the two-card seam widenings, the malformed-answer
  matrix and the launcher tests planned for it (BUG-LOG BL-11/12/25) are
  pending.
- **`-Darena.fixtures.refresh=true`** — `ProtocolContractTest` compares the
  requests the engine emits against the committed fixtures in
  `forge-arena/runner/tests/fixtures/engine/*.json` and fails, naming the
  decision types that drifted, instead of rewriting tracked files. After
  reviewing a deliberate protocol change, run the test once with this flag
  to rewrite them, then commit the fixtures.

Test-suite knobs (both revertible, see docs/IMPLEMENTATION-PLAN.md §8):
- `arena.mailbox.poll.ms` — surefire pins 5ms so E2E mailbox tests skip
  live-game pacing (live default 75ms; never set outside tests).
- `arena.test.divergence.simTurnCap` (default 5; REVERT with `=8`) and
  `arena.test.divergence.seedTries` — AiAssignmentDivergenceTest knobs;
  measured 2026-08-28: profile divergence at seed 5, sim divergence at
  seed 1, cap 8→5 cut the sim game 114s→15s with the invariant intact.

Two flags are load-bearing:

- **`-am` (also-make) is mandatory.** `forge-arena` depends on the upstream
  modules (`forge-core`, `forge-game`, `forge-ai`, `forge-gui`,
  `forge-gui-desktop`) and on the reactor to resolve the `${revision}`
  ci-friendly parent version. `mvn -pl forge-arena package` **without `-am`
  fails** to resolve the parent, especially offline.
- **`-o` only works after a warm `~/.m2`.** Omit it on a fresh machine or the
  first build fails with unresolved-artifact errors.

A green `package` build produces everything downstream tooling needs:

- `forge-gui-desktop/target/forge-gui-desktop-<version>-jar-with-dependencies.jar`
  (the fat runtime jar),
- `forge-arena/target/classes` (compiled arena classes), and
- `forge-arena/target/classpath.txt` (auto-generated by a bound
  `maven-dependency-plugin` execution — no separate step).

### Do NOT reach for `-Dcheckstyle.skip=true`

Checkstyle runs at the `validate` phase across all modules and is part of a
green build. If checkstyle fails, fix the violation (usually an unused import)
rather than skipping the gate — a skipped gate is how a red build reaches the
`master`/`arena` branch unnoticed.

### Tests

The arena pom runs its test suite as part of `package`. To run a single test:

```sh
mvn -o -pl forge-arena -am test \
  -Dtest=SomeTest -Dsurefire.failIfNoSpecifiedTests=false
```

`-Dsurefire.failIfNoSpecifiedTests=false` is needed because `-am` also visits
upstream modules that contain no matching test.

## Packaging the distributable (forge-light-llm tarball)

After a **green** `mvn -o -pl forge-arena -am package`:

```sh
# assemble the portable package tree (Project-2 surface only):
forge-arena/packaging/build-light-package.sh --force   # dest: <repo>/../forge-light-llm

# tar it (COPYFILE_DISABLE avoids macOS ._ AppleDouble files in the archive):
COPYFILE_DISABLE=1 tar -czf forge-light-llm-YYYYMMDD.tar.gz -C <repo>/.. forge-light-llm
```

`build-light-package.sh` is self-documenting (its header is the package
manifest) and refuses to clobber an existing dest without `--force`. It ships
compiled classes + the fat jar + the ten bundled decks; no source, no Maven,
so the recipient never builds anything — they run it directly. Not shipped:
`runner/tests/` (and with it `runner/replay.py`, which needs those fixtures),
`runner/logs/`, ratings state, and every `decks/*/dossier/.cache/` directory
(BL-18, 2026-09-04: the DeckCheck payloads there carry the account's
username; the build fails if a `.cache` reaches the package tree).

## Runtime notes

- Maven settings: `.mvn/maven.config` forces `.mvn/local-settings.xml`. That
  file only defines a `cardforge-repo` server for `mvn deploy`
  (`<distributionManagement>`, a local `file://` URL) — it is irrelevant to
  building and needs no credentials for `package`.
- Runtime outputs (`forge-arena/runner/logs/`, `runner/results/`,
  `runner/ratings*`) are gitignored; they are regenerated per run.
